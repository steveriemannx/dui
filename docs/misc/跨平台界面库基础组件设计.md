# Basic Component Design of a Cross-Platform (Windows/Linux/macOS) C++ UI Library
When developing a cross-platform (Windows/macOS/Linux) C++ UI library, the core is first to cover **cross-platform common basic components** (satisfying 90% of routine development needs) while balancing each platform's native interaction logic with visual consistency. The component design must follow an "abstract layer with unified interfaces + platform layer with adaptation implementations" architecture. Below are the required basic component categories and their core details:

## I. Core Foundation Layer Components (underlying capabilities that support every UI)
These components do not present UI directly, but they determine the cross-platform stability and fundamental capabilities of the UI library, and every visual component depends on them.

| Component/Module | Core functionality | Cross-platform adaptation points |
|-----------|----------|----------------|
| Window core (Window) | 1. Basic window create/destroy/hide/always-on-top/fullscreen<br>2. Window size/position adjustment, multi-monitor adaptation<br>3. Window events (close/minimize/maximize/move/repaint)<br>4. Modal/non-modal window support | - Windows: adapt HWND and the Win32 message loop;<br>- macOS: adapt NSWindow and Cocoa event handling;<br>- Linux: adapt X11/Wayland and GTK/KDE window managers;<br>- Unified cross-platform rendering logic for window styles (rounded corners/shadow) |
| Application framework (Application) | 1. Cross-platform main loop (message pump/event loop)<br>2. Application lifecycle management (startup/exit/pause)<br>3. Resource management (global fonts/icons/configuration)<br>4. Command-line argument parsing, logging | - Hide main-loop differences across platforms (Windows `GetMessage`/macOS `NSRunLoop`/Linux `poll`);<br>- Unified application-level exception capture and exit code definitions |
| Event system (Event System) | 1. Unified event model (mouse/keyboard/touch/window events)<br>2. Event dispatch/bubbling/capture mechanism<br>3. Custom event support (cross-thread event delivery)<br>4. Event filters (intercept/modify events) | - Unified event types (e.g. left mouse button down: `EVT_MOUSE_LEFT_DOWN`) to hide platform-native event differences;<br>- Touch event support (macOS/iOS trackpads, Windows touch screens, Linux touch devices);<br>- Solve event compatibility issues across Linux desktop environments (GNOME/KDE) |
| Render context (Render Context) | 1. Cross-platform drawing context (wraps GDI/Quartz/OpenGL/Vulkan)<br>2. Double-buffered rendering (avoids flicker)<br>3. High-DPI adaptation (Retina/4K screens, synchronized scaling ratios)<br>4. Drawing graphics primitives (points/lines/rectangles/paths/text) | - Abstract the render interface so the backend can be switched (e.g. Skia for 2D, OpenGL for 3D);<br>- Unified high-DPI logic (Windows DPI awareness, macOS Retina scaling, Linux Xft/DPI settings);<br>- Anti-aliasing and alpha-channel rendering support |

## II. Basic Container Components (the core skeleton of UI layout)
Container components host and arrange other components, and need cross-platform-consistent layout rules (e.g. flow, flex, absolute layout).

| Component | Core functionality | Cross-platform adaptation points |
|------|----------|----------------|
| Basic Window / Dialog | See "Core Foundation Layer"; additionally:<br>1. Dialogs are divided into "modal dialogs" (block the parent window) and "non-modal dialogs";<br>2. Support system-native dialog styles (e.g. Windows dialog borders, macOS sheet popups) | - Avoid conflicts between custom window styles and platform-native ones (e.g. macOS windows have no maximize button; Linux window decorations depend on the desktop environment);<br>- Dialog button layout adapted to platform conventions (Windows "OK/Cancel" on the right, macOS "Cancel/OK" on the right) |
| Panel | 1. An undecorated basic container for grouping components;<br>2. Supports background color/background image and border styles;<br>3. Nested layout (other containers/components can be placed inside a panel) | - Unified border rendering logic (Windows GDI borders, macOS Quartz borders, Linux Cairo borders);<br>- Cross-platform-consistent background image scaling/tiling rules |
| Layout Container | The core is wrapping common layout algorithms to avoid manual component positioning:<br>1. Horizontal layout (HBox): components arranged horizontally;<br>2. Vertical layout (VBox): components arranged vertically;<br>3. Grid layout (Grid): row/column alignment (e.g. tables, forms);<br>4. Flex layout (Flex): adaptive space allocation (priority/weight);<br>5. Absolute layout (Absolute): manually specify coordinates/size | - Hide platform layout engine differences (e.g. macOS AutoLayout, Windows LayoutManager, Linux GTK layout);<br>- Unified configuration of layout spacing (Margin/Padding) and alignment (left/center/right, top/center/bottom);<br>- Responsive adaptation (components auto-adjust when the window is resized) |
| Scroll container (ScrollView) | 1. Single-axis/dual-axis scrolling (horizontal/vertical);<br>2. Scrollbar styles (native/custom);<br>3. Scroll events and scroll position control;<br>4. Lazy loading for large content | - Adapt scrollbar interaction on each platform (Windows: clicking the blank scrollbar area jumps a page; macOS: auto-hiding scrollbars; Linux: scrollbar style follows the desktop environment);<br>- Unified cross-platform touch scrolling (inertial scrolling) implementation |
| Split panel (Splitter) | 1. Horizontal/vertical split containers (e.g. left/right columns, top/bottom rows);<br>2. Drag to adjust the splitter position;<br>3. Splitter styles, min/max size limits | - Drag feel adapted to the platform (Windows drag damping, macOS smooth dragging, Linux lightweight dragging);<br>- Unified visual feedback for the splitter hover state |

## III. Basic Interaction Components (the main vehicle for user operations)
These components are the core of user interaction with the program: interaction logic must be cross-platform consistent, while visuals can adapt to native styles.

| Component | Core functionality | Cross-platform adaptation points |
|------|----------|----------------|
| Button | 1. Basic buttons (text/icon/icon+text);<br>2. States: normal/hover/pressed/disabled/focused;<br>3. Special buttons: checkbox, radio button, toggle button;<br>4. Button group (RadioGroup): manages radio button exclusivity | - Visual styles switchable to "native style" (e.g. Windows Fluent buttons, macOS liquid-glass buttons, Linux GTK buttons);<br>- Consistent keyboard interaction (Enter/Space triggers the button);<br>- Check/radio button checkmark styles adapted to platform conventions |
| Text input (Input/TextField/TextArea) | 1. Single-line input (TextField), multi-line input (TextArea);<br>2. Input restrictions (length/regex/number/password);<br>3. Placeholder, word wrap, scrolling;<br>4. Input method adaptation (Chinese/Japanese etc.), caret control;<br>5. Text selection, copy/paste/cut | - Hide platform IME interface differences (Windows IME, macOS Input Method, Linux fcitx);<br>- Caret style and selected-text highlight color adapted to the platform-native look;<br>- Solve text rendering differences across Linux desktop environments |
| Dropdown (ComboBox/DropDown) | 1. A dropdown list shows options for single selection;<br>2. Editable dropdown (input + selection);<br>3. Option filtering, scrolling;<br>4. Expand/collapse animation, disabled state | - Dropdown popup position adaptation (Windows: below the button; macOS: flush with the button edge; Linux: follows the desktop environment);<br>- Cross-platform handling so the dropdown list is not clipped by window boundaries |
| List (List/ListView) | 1. Single/multi-column lists, item rendering;<br>2. Item selection (single/multi), hover/selected states;<br>3. Scrolling, lazy loading, adaptive item height;<br>4. List header, column width adjustment | - Cross-platform consistency of item click/double-click events;<br>- Large-list performance optimization (virtual lists, rendering only the visible area);<br>- List scroll performance adaptation across Linux desktop environments |
| Menu (Menu/MenuBar/ContextMenu) | 1. Top menu bar (MenuBar), context menu (right-click menu);<br>2. Menu items (text/icon/shortcut/separator);<br>3. Submenus, disabled/checked states;<br>4. Shortcut triggering (e.g. Ctrl+C/Command+C) | - Menu bar position adaptation (Windows: inside the window; macOS: at the top of the system; Linux: follows the desktop environment);<br>- Unified shortcut mapping (e.g. cross-platform conversion of Ctrl/Command and Alt/Option);<br>- Context menu popup position adaptation (avoid overflowing the screen) |

## IV. Basic Display Components (the core of information presentation)
These components focus on information display without complex interaction, but must maintain cross-platform visual consistency.

| Component | Core functionality | Cross-platform adaptation points |
|------|----------|----------------|
| Text (Label) | 1. Single/multi-line text, rich text (simple styles: color/font/size);<br>2. Text alignment (left/center/right, top/center/bottom);<br>3. Word wrap, ellipsis (show ... when exceeding the width);<br>4. Icon + text combination support | - Unified font rendering (wrap FreeType/system font interfaces to avoid font differences across platforms);<br>- Rich text keeps only cross-platform common styles (avoid platform-specific text formats) |
| Image (Image/ImageView) | 1. Load common formats (PNG/JPG/BMP/SVG);<br>2. Scale modes (stretch/proportional/center/crop);<br>3. Transparency, rounded corners, borders;<br>4. Basic animated image (GIF) playback | - Unified cross-platform image decoding (wrap open-source libraries such as libpng/libjpeg to avoid system decoding differences);<br>- Consistent SVG vector rendering (avoid scaling distortion on macOS/Linux) |
| ProgressBar | 1. Linear progress bar (horizontal), circular progress bar (optional);<br>2. Progress value (0-100), progress text (e.g. 50%);<br>3. Progress color, background color, disabled state | - Linear progress bar style adapted to the platform (Windows segmented progress, macOS smooth progress, Linux minimalist progress);<br>- Consistent cross-platform animation smoothness for progress updates |
| Slider | 1. Horizontal/vertical slider, value range (minimum/maximum);<br>2. Step size, current value, drag adjustment;<br>3. Tick marks, tooltip value display | - Slider drag feel (damping/smooth) adapted to platform conventions;<br>- Tick and thumb styles switchable to native styles |
| Separator | 1. Horizontal/vertical separator lines;<br>2. Color, thickness, spacing | - Separator visual style adapted to the platform (Windows thin gray line, macOS light gray line, Linux follows the theme);<br>- Unified spacing calculation when nested in layouts |

## V. Helper Tool Components (cross-platform tools that improve development efficiency)
These components are not visual UI, but they greatly reduce cross-platform development cost and are the "infrastructure" of the UI library.

| Component/Tool | Core functionality |
|-----------|----------|
| ResourceManager | 1. Cross-platform resource loading (fonts/icons/images/configuration files);<br>2. Unified resource paths (hide the Windows `\` vs macOS/Linux `/` difference);<br>3. Resource caching and release management |
| Style/Theme system | 1. Unified style interface (colors/fonts/margins/rounded corners);<br>2. Native theme adaptation (Windows light/dark, macOS system theme, Linux GTK themes);<br>3. Custom themes, style inheritance/override |
| Timer | 1. One-shot/repeating timers;<br>2. Cross-platform time precision (millisecond level);<br>3. Timer callbacks (triggered on the main thread to avoid thread safety issues) |
| Clipboard | 1. Text/image copy/paste;<br>2. Unified cross-platform clipboard interface;<br>3. Clipboard data format conversion |
| Logger | 1. Leveled logging (Debug/Info/Warn/Error);<br>2. Cross-platform log output (console/file);<br>3. Unified log format |

## VI. Core Design Principles (ensuring cross-platform usability)
1. **Interface abstraction**: all components provide unified C++ abstract interfaces (e.g. the `Window` class), implemented underneath via a platform adaptation layer (e.g. `Win32Window`/`CocoaWindow`/`X11Window`); upper-level business code need not care about platform details;
2. **Minimal differentiation**: prioritize implementing "common interaction logic" across platforms; platform-specific features (e.g. macOS TouchBar, Windows taskbar progress) are extension components rather than part of the basic library;
3. **Performance first**: basic components need cross-platform performance optimization (e.g. virtual lists, double buffering, lazy resource loading) to avoid lag on low-end Linux devices;
4. **Native compatibility**: support switching between "native style" and "custom style" to satisfy users' demand for "platform-native visuals" (e.g. the liquid-glass effect of macOS buttons, Windows Fluent rounded corners).

## Summary
Basic components covering the five categories "core foundation + containers + interaction + display + helper tools" are enough to satisfy 90% of cross-platform C++ application development needs; advanced components (e.g. Table, TreeView, TabView) can be built on top later. The core is to hide platform differences behind "unified interfaces in the abstract layer" while keeping each component's interaction logic and visual style both unified across platforms and adapted to native conventions.
